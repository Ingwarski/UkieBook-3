## Wireframe Principles

1. Структура перед стилем: ієрархія, групування та CTA-акценти без кольорів, типографіки й токенів (власність design-brief).
2. Роздільність — насамперед інтервалами й групуванням; рамки й тіні — останній засіб (guardrails).
3. Без суцільних карток на весь застосунок; картки лише там, де є повторюваний обʼєкт каталогу/списку.
4. Реалістичні слоти вмісту (назви книжок, гривневі ціни, статуси) — без lorem ipsum.
5. Кожен екран має рівно один первинний CTA; вторинні дії візуально підпорядковані.
6. Стани описуються як дельти від дефолтного блупринта; перелік станів — власність screen-map.

## Screen Blueprints

### S-01 Каталог

- Source Screen: S-01 (`/`)
- Purpose: знайти книжку за назвою, автором, жанром чи знижкою (FR-CAT-2).
- Primary User Intent: покупець шукає, що почитати українською.
- Layout Structure:

```
+------------------------------------------------------------------------+
| UkieBook | Каталог | Жанри | Знижки | Авторам | пошук | Кошик(2)       |
+------------------------------------------------------------------------+
|                         Затишні вечори                              |
|                   з українською книжкою                            |
|     Електронні книжки EPUB і MOBI миттєво у вашу бібліотеку.      |
+------------------------------------------------------------------------+
| 5 квадратнокутних Обкладинок 2:3: повністю видимі, центральна вище |
+------------------------------------------------------------------------+
|  4 горизонтальні glass-плитки: міні-Обкладинка | назва | Автор | грн |
+------------------------------------------------------------------------+
| Прозора формула: з кожних 100 грн | 35% | 65% — автору              |
+------------------------------------------------------------------------+
| Продовження функціонального Каталогу: активні фільтри/результати   |
| [Жанр] [Зі Знижкою] [Сортування] · responsive grid P-2 · пагінація |
+------------------------------------------------------------------------+
```

- Primary CTA: картка книжки → перехід на S-02.
- Secondary Actions: `Жанри` і `Знижки` активують відповідні фільтри; `Авторам` веде через S-03 до S-17/S-10; пошук у хедері; Кошик → S-04; сортування в продовженні результатів.
- Inputs And Content: exact fixture/ієрархія затвердженого hero-блоку; точний hero-підзаголовок `Електронні книжки EPUB і MOBI миттєво у вашу бібліотеку.`; поле пошуку (назва/Автор), Жанр, `Зі Знижкою`, сортування, повний список P-2 після формули. S-01 використовує сім різних реалістичних 2:3 cover artworks із різними назвами, запеченими безпосередньо у файли зображень; поверх обкладинок заборонено накладати live title text. Усі Обкладинки мають `border-radius: 0`.
- States (дельти): завантаження — hero-shell збережений, Обкладинки/плитки/результати стають геометричними скелетонами; порожній пошук — hero-shell збережений, зона результатів показує «Нічого не знайдено» + скидання; помилка — інлайн у зоні результатів; довгий список — пагінація. Authenticated header додає семантичний доступ до Бібліотеки/профілю без творчого перекомпонування baseline.
- Notes For Design Brief: блок від хедера до стрічки формули є locked 1:1 desktop composition. Усі пʼять Обкладинок першого shelf-row повністю видимі до нижнього краю в default viewport і не кліпаються контейнером. Функціональні результати додаються після нього або через baseline-контроли; не вставляти новий рядок між hero, shelf, плитками й formula.

### S-02 Сторінка книжки

- Source Screen: S-02 (`/books/{id}`)
- Purpose: показати все для рішення про покупку (FR-CAT-3).
- Primary User Intent: оцінити книжку, прочитати фрагмент, купити.
- Layout Structure:

```
+----------------------+---------------------------+
| Обкладинка (велика)  | Назва (h1)                |
|                      | Автор (публічне імʼя)     |
|                      | Жанр · Рейтинг ★          |
|                      | Ціна [~стара~ нова] грн   |
|                      | [Додати в кошик]  ← CTA   |
|                      | [Читати фрагмент]         |
+----------------------+---------------------------+
| Опис книжки (довгий текст, згортання)            |
+--------------------------------------------------+
| Безкоштовний фрагмент (розгортається інлайн)     |
+--------------------------------------------------+
| Відгуки: ★ рейтинг, список; форма S-08 (покупцям)|
+--------------------------------------------------+
```

- Primary CTA: «Додати в кошик» (FR-PAY-2).
- Secondary Actions: «Читати фрагмент» (FR-CAT-3); пагінація відгуків.
- Inputs And Content: обкладинка, назва, автор, жанр, опис, ціна зі знижкою (закреслена стара / нова + дати дії), рейтинг, відгуки, фрагмент.
- States (дельти): недоступна книжка (FR-LIC-4) — блок ціни/CTA замінено повідомленням «Книжка недоступна»; фрагмент відкрито — інлайн-читання; знижка неактивна — одна ціна; довгі відгуки — пагінація; завантаження — скелетон двох колонок.
- Notes For Design Brief: фрагмент — ключовий довірчий елемент; його типографіка має демонструвати якість адаптивного видання.

### S-03 Вхід

- Source Screen: S-03 (`/login`)
- Purpose: автентифікація виключно через Google/Facebook (FR-AUTH-1).
- Primary User Intent: швидко увійти й повернутися до перерваної дії.
- Layout Structure: одна колонка по центру — заголовок, пояснення «Вхід потрібен для покупки чи публікації», кнопка Google, кнопка Facebook, юридична примітка.
- Primary CTA: «Увійти через Google» (перша кнопка).
- Secondary Actions: «Увійти через Facebook»; повернення назад.
- Inputs And Content: лише дві OAuth-кнопки — жодних полів пароля.
- States (дельти): помилка OAuth — інлайн-повідомлення над кнопками з повтором; після успіху — редирект на екран-джерело (S-04 чи `/author/*`).
- Notes For Design Brief: мінімальний екран; довіра через впізнавані кнопки провайдерів.

### S-04 Кошик

- Source Screen: S-04 (`/cart`)
- Purpose: оплатити кілька книжок одним платежем (FR-PAY-2).
- Primary User Intent: перевірити позиції й перейти до оплати.
- Layout Structure:

```
+--------------------------------------------------+
| Заголовок «Кошик»                                |
+--------------------------------------------------+
| Позиція: [мін.обкл] Назва / Автор   ціна  [✕]   |
| Позиція: [мін.обкл] Назва / Автор   ~ціна~ нова |
+--------------------------------------------------+
| Разом: N грн                                     |
| [Оплатити] ← CTA                                 |
+--------------------------------------------------+
```

- Primary CTA: «Оплатити» → S-05 (після входу; гостю — спершу S-03).
- Secondary Actions: видалити позицію; «Продовжити покупки» → S-01.
- Inputs And Content: список позицій (обкладинка, назва, автор, ціна/знижка), сума разом у грн.
- States (дельти): порожній кошик — зона списку замінена повідомленням + CTA «До каталогу»; вимога входу — під CTA примітка «Для оплати увійдіть», CTA веде на S-03; помилка — інлайн.
- Notes For Design Brief: сума «Разом» — другий за вагою елемент після CTA.

### S-05 Оплата mono (зовнішня)

- Source Screen: S-05 (зовнішній редирект)
- Purpose: приймання платежу (FR-PAY-3).
- Primary User Intent: заплатити карткою, Apple Pay чи Google Pay.
- Layout Structure: Not applicable: поверхня належить провайдеру mono; платформа контролює лише перехід і повернення (OQ-SM1).
- Primary CTA: на боці провайдера.
- Secondary Actions: скасування → повернення в S-04.
- Inputs And Content: на боці провайдера.
- States: перехід (лоадер «Переходимо до оплати…»); повернення успіх/невдача → S-06.
- Notes For Design Brief: лише перехідний лоадер у стилі платформи.

### S-06 Результат оплати

- Source Screen: S-06 (`/checkout/result`)
- Purpose: підтвердити результат і повести в бібліотеку (FR-PAY-4).
- Primary User Intent: переконатися, що книжки придбано, і забрати їх.
- Layout Structure: одна колонка — статус-заголовок, перелік придбаних книжок, CTA.
- Primary CTA: успіх — «Перейти в бібліотеку» → S-07.
- Secondary Actions: успіх — «До каталогу»; невдача — «Повернутися в кошик» → S-04 (кошик збережено).
- Inputs And Content: перелік книжок з цінами; примітка про email (E-01).
- States (дельти): успіх — перелік + CTA бібліотеки; невдача — причина без техдеталей + CTA кошика; очікування підтвердження платежу — лоадер.
- Notes For Design Brief: success-стан — климакс подорожі покупця; заслуговує на виразний момент.

### S-07 Бібліотека

- Source Screen: S-07 (`/library`)
- Purpose: доступ до куплених книжок і файлів (FR-LIB-1/2/3).
- Primary User Intent: завантажити EPUB/MOBI, повернутися до книжки.
- Layout Structure:

```
+--------------------------------------------------+
| Заголовок «Бібліотека»  [? Як відкрити файли]    |
+--------------------------------------------------+
| Позиція: [обкл] Назва / Автор                    |
|   [EPUB ↓] [MOBI ↓]   «Оновлено: дата» (бейдж)   |
|   [Залишити відгук →] [Повернення коштів]        |
+--------------------------------------------------+
```

- Primary CTA: кнопки завантаження EPUB/MOBI на кожній позиції.
- Secondary Actions: «Залишити відгук» → S-02/S-08; «Повернення коштів» → S-09; довідка «Як відкрити файли» (OQ-SM2, дефолт прийнято).
- Inputs And Content: список куплених книжок; бейдж «Оновлено» після схваленого оновлення (FR-UPD-3).
- States (дельти): порожня бібліотека — повідомлення + CTA «До каталогу»; помилка завантаження — інлайн біля кнопки з повтором; оновлена версія — бейдж дати.
- Notes For Design Brief: кнопки форматів — рівнозначні; бейдж оновлення — вторинний акцент.

### S-08 Форма відгуку (поверхня на S-02)

- Source Screen: S-08
- Purpose: рейтинг і відгук від підтвердженого покупця (FR-REV-1/2).
- Primary User Intent: поділитися враженням.
- Layout Structure: інлайн-блок у секції відгуків S-02 — зірки, текстове поле, кнопка.
- Primary CTA: «Опублікувати відгук».
- Secondary Actions: скасувати (згорнути форму).
- Inputs And Content: рейтинг 1–5 (обовʼязковий), текст відгуку.
- States (дельти): прихована (не Покупець, FR-REV-1); надіслано — форму замінено повідомленням «Відгук на модерації» (FR-MOD-5); опубліковано — відгук у списку; не опубліковано — нейтральний статус без обіцянки buyer-facing Категорії причини, якої PRD не визначає.
- Notes For Design Brief: стан «на модерації» не повинен виглядати як помилка.

### S-09 Запит на повернення (модал із S-07)

- Source Screen: S-09
- Purpose: подати запит на повернення коштів (FR-REF-1).
- Primary User Intent: повернути гроші за покупку.
- Layout Structure: модал P-6 — назва книжки, поле причини, примітка про ручний розгляд менеджером (FR-REF-2).
- Primary CTA: «Надіслати запит».
- Secondary Actions: скасувати.
- Inputs And Content: причина (текст), автопідставлена книжка/замовлення.
- States (дельти): надіслано — модал замінено підтвердженням; статус розгляду — бейдж на позиції в S-07 («Розглядається / Схвалено / Відхилено»).
- Notes For Design Brief: нейтральний тон без відмовляння.

- Purpose: огляд усіх книжок автора зі статусами (FR-MOD-3).
- Primary User Intent: побачити стан кожної книжки, почати нову публікацію.
- Layout Structure:

```
+--------------------------------------------------+
| Заголовок «Мої книжки»       [Опублікувати нову] |
+--------------------------------------------------+
| Рядок: [обкл] Назва  · [Статус P-4] · продажі    |

+--------------------------------------------------+
```

- Primary CTA: «Опублікувати нову книжку» → S-11.
- Secondary Actions: рядок книжки → S-13.
- Inputs And Content: список книжок: обкладинка, назва, статус (чернетка / на модерації / ручна перевірка / відхилено+категорія / опубліковано), короткі продажі.
- States (дельти): перший вхід — зона списку замінена порожнім станом «Опублікуйте першу книжку» з CTA; завантаження — скелетон списку.
- Notes For Design Brief: статусні бейджі P-4 — спільна мова з S-13/S-18.

### S-11 Майстер публікації

- Source Screen: S-11 (`/author/publish`)
- Purpose: провести автора від рукопису до подання (FR-PUB-1..9).
- Primary User Intent: опублікувати книжку без технічних знань.
- Layout Structure:

```
+--------------------------------------------------+
| Кроки P-5: 1 Рукопис · 2 Опис та ілюстрації ·    |
|  3 Обкладинка · 4 Жанр/ціна/фрагмент ·           |
|  5 Попередній перегляд · 6 Права й ліцензія      |
+--------------------------------------------------+
| Зона активного кроку (одна колонка)              |
| [Назад]                       [Далі] ← CTA       |
+--------------------------------------------------+
```

Кроки:
1. Рукопис: dropzone DOCX/TXT + кнопка «Імпорт із Google Docs» (FR-PUB-1); примітка про базове технічне впорядкування (FR-PUB-2).
2. Опис та ілюстрації: поле опису; завантаження ілюстрацій у потік тексту (FR-PUB-3/4).
3. Обкладинка: dropzone або перемикач «Згенерувати просту обкладинку» з превʼю шаблону (FR-PUB-5).
4. Жанр/ціна/фрагмент: селект одного жанру; поле ціни в грн із підказкою діапазону (FR-PUB-9); вибір безкоштовного фрагмента (FR-PUB-4, A-3).
5. Попередній перегляд видання → S-12.
6. Права й ліцензія: читабельний текст Декларації прав + окремий чекбокс (FR-PUB-8); окремий блок наслідків п'ятирічного невиключного права без раннього зняття + окремий чекбокс (FR-LIC-2/3); кнопка «Подати книжку» активна лише після обох підтверджень.

- Primary CTA: «Далі» / на кроці 6 — «Подати книжку».
- Secondary Actions: «Назад»; збереження чернетки (повернення без втрати).
- Inputs And Content: перелічені по кроках.
- States (дельти): завантаження файлу — прогрес у dropzone; помилка формату/зламаний файл — інлайн у dropzone (FR-MOD-1); Чернетка збережена — бейдж; будь-яке з двох підтверджень відсутнє — CTA disabled з інлайн-поясненням; подано — редирект на S-10 зі статусом «На модерації».
- Notes For Design Brief: крок 6 — юридично чутливий; текст декларації має бути читабельним, не дрібним шрифтом.

### S-12 Попередній перегляд видання (крок майстра)

- Source Screen: S-12 (`/author/publish/preview`)
- Purpose: єдина точка контролю якості конвертації (FR-PUB-6).
- Primary User Intent: переконатися, що книжка виглядає як слід.
- Layout Structure: дві вкладки — «Книжка» (рендер Адаптивного видання: структура розділів, Ілюстрації в потоці) і «Сторінка книжки» (попередній перегляд S-02 з Обкладинкою, описом, Безкоштовним фрагментом); перемикач desktop/mobile.
- Primary CTA: «Все гаразд, далі» → крок 6.
- Secondary Actions: «Повернутися до редагування» → відповідний крок S-11 без втрати даних.
- Inputs And Content: рендер Книжки; попередній перегляд Сторінки книжки.
- States (дельти): рендеринг — лоадер «Готуємо видання…»; помилка конвертації — зона рендера замінена повідомленням із причиною і CTA «Завантажити інший файл».
- Notes For Design Brief: попередній перегляд Сторінки книжки структурно відповідає S-02; це не Безкоштовний фрагмент і не внутрішня читалка.

### S-13 Керування книжкою Автора

- Source Screen: S-13 (`/author/books/{id}`)
- Purpose: керування опублікованою книжкою (FR-MOD-3, FR-CAT-4, FR-UPD-1).
- Primary User Intent: перевірити статус, керувати знижкою, подати оновлення.
- Layout Structure:

```
+--------------------------------------------------+
| [обкл] Назва · Статус P-4                        |
|        Категорія причини (якщо відхилено)        |
+--------------------------------------------------+
| Секція «Знижка»: активна/запланована/нема        |
|  [Створити знижку]: % або нова ціна, дати з-по   |
+--------------------------------------------------+
| Секція «Оновлення»: [Подати оновлення] → S-14    |
|  Статус: очікує накопичення 250 грн / на модер.  |
+--------------------------------------------------+
| Продажі книжки (короткий блок, лінк на S-15)     |
+--------------------------------------------------+
```

- Primary CTA: контекстний — «Створити знижку» або «Подати оновлення».
- Secondary Actions: перегляд публічної S-02; лінк на S-15.
- Inputs And Content: форма знижки (значення, дата початку, дата завершення — FR-CAT-4); статуси оновлення (FR-UPD-2).
- States (дельти): відхилено — вгорі категорія причини (FR-MOD-3); знижка запланована/активна/завершена — відповідний бейдж; оновлення чекає накопичення — пояснення суми, що бракує.
- Notes For Design Brief: категорія причини відхилення — стримана, без тону покарання.

### S-14 Подання оновлення

- Source Screen: S-14 (`/author/books/{id}/update`)
- Purpose: подати оновлений Рукопис/Обкладинку (FR-UPD-1/2).
- Primary User Intent: виправити чи оновити опубліковану книжку.
- Layout Structure: одна колонка — dropzone нового рукопису (опційно), dropzone нової обкладинки (опційно), попередження «Оновлення коштує 250 грн, сума буде утримана з наступної виплати», CTA.
- Primary CTA: «Подати оновлення».
- Secondary Actions: скасувати → S-13.
- Inputs And Content: файли; вартість 250 грн; для засновника попередження відсутнє (FR-FND-4).
- States (дельти): нарахувань < 250 грн — CTA активна, після подання статус «Очікує накопичення» (FR-UPD-2); подано — статус «На модерації» (FR-MOD-4); засновник — блок вартості прихований.
- Notes For Design Brief: фінансове попередження — до CTA, не після.

### S-15 Винагорода

- Source Screen: S-15 (`/author/rewards`)
- Purpose: прозорість продажів, нарахувань і виплат (FR-REW-5/6).
- Primary User Intent: зрозуміти, скільки зароблено і коли виплата.
- Layout Structure:

```
+--------------------------------------------------+
| Зведення: Нараховано за місяць · Статус виплати  |
| Формула: 100 грн = 35 грн платформі · 65 грн вам |
+--------------------------------------------------+
| Таблиця за Книжками (P-3):                       |
| Книжка | Продажі | Валовий дохід | Нарах. | Виплата-статус |
+--------------------------------------------------+
| Історія виплат: місяць · сума · статус           |
+--------------------------------------------------+
```

- Primary CTA: за незаповнених даних — «Заповнити платіжні дані» → S-16; інакше екран інформаційний.
- Secondary Actions: розгортання місяця в історії.
- Inputs And Content: публічна робоча формула `35% платформі / 65% автору` від фактично сплаченої ціни (FR-REW-2; юридична/бухгалтерська готовність лишається release-gate), таблиця за Книжками без даних Покупців із окремим статусом Виплати кожної Книжки (FR-REW-6), статуси: нараховано / очікує Виплати / виплачено / перенесено <100 грн (FR-PYT-4). Внутрішні `29% + 6%` не показуються Автору.
- States (дельти): немає продажів — таблиця замінена порожнім станом; не заповнено S-16 — банер-блокер першої виплати (FR-AUTH-4).
- Notes For Design Brief: формула — постійно видима; прозорість тут будує довіру всієї платформи.

### S-16 Платіжні дані й модель винагороди

- Source Screen: S-16 (`/author/payout-details`)
- Purpose: зібрати дані перед першою виплатою (FR-AUTH-4, FR-REW-4).
- Primary User Intent: отримати першу виплату.
- Layout Structure: одна колонка — вибір Моделі винагороди (радіо: ФОП / фізична особа/роялті з коротким поясненням кожної), поля договірних/платіжних/податкових даних, CTA.
- Primary CTA: «Зберегти дані».
- Secondary Actions: повернутися в S-15.
- Inputs And Content: модель винагороди; договірні, платіжні, податкові поля (склад — OQ-W1).
- States (дельти): не заповнено — банер у S-15; збережено — підтвердження, менеджер бачить вибір у S-19 (FR-REW-4).
- Notes For Design Brief: пояснення моделей — простою мовою, без юридичного жаргону; це найчутливіша форма продукту.

- Primary CTA: «Зберегти».

### S-18 Черга Ручної перевірки (Менеджер)

- Source Screen: S-18 (`/admin/moderation`)
- Purpose: Ручна перевірка Ризикових випадків і прибирання ризикової опублікованої Книжки на підставі FR-LIC-4 (FR-MOD-2/4/5).
- Primary User Intent: менеджер швидко розбирає чергу.
- Layout Structure: список із фільтром типу (книжка / оновлення / відгук); рядок: тип, назва/фрагмент, сигнал ШІ; розгортання деталей; дії.
- Primary CTA: «Схвалити» на розгорнутому обʼєкті.
- Secondary Actions: для Книжки/Оновлення книжки — «Відхилити» з обовʼязковим вибором Категорії причини (FR-MOD-3); для відгуку — «Не публікувати» без обіцянки пояснення Покупцеві; для ризикової вже опублікованої Книжки — «Прибрати з Каталогу» з P-6 і підставою FR-LIC-4.
- Inputs And Content: обʼєкт перевірки, сигнал ШІ, Категорія причини для матеріалів Автора; підтвердження наслідку при прибиранні Книжки.
- States (дельти): порожня черга — «Все перевірено»; після рішення — обʼєкт зникає зі списку, статуси оновлюються в S-10/S-13/S-08.
- Notes For Design Brief: службовий екран; щільність важливіша за естетику.

### S-19 Таблиця виплат (менеджер)

- Source Screen: S-19 (`/admin/payouts`)
- Purpose: місячні виплати з ручним підтвердженням (FR-PYT-1..4).
- Primary User Intent: перевірити суми й підтвердити виплати по одному автору.
- Layout Structure:

```
+--------------------------------------------------+
| Селектор місяця: [< Червень 2026 >]              |
+--------------------------------------------------+
| Таблиця: Автор | Модель | Продажі | Платформа net 29% |
| Податк. компонент 6% | Автор 65% | До виплати | Статус |
|                                      [Підтвердити]|
+--------------------------------------------------+
```

- Primary CTA: «Підтвердити факт виплати» в кожному рядку окремо після фактичного переказу (FR-PYT-3).
- Secondary Actions: розгортання рядка (деталі за книжками, утримання 250 грн за оновлення — FR-UPD-2); перемикання місяця.
- Inputs And Content: рядок автор×місяць: сума продажів, `29%` чистого заробітку платформи, `6%` податкового компонента платформи, `65%` автора, сума до виплати (FR-PYT-2), модель винагороди (FR-REW-4), позначка засновника 100% (FR-FND-2). Кожен звичайний рядок доводить інваріант `29 + 6 + 65 = 100`; `35%` платформи дорівнює `29% + 6%`.
- States (дельти): порожній місяць — повідомлення; <100 грн — рядок зі статусом «Перенесено» без кнопки (FR-PYT-4); факт підтверджено — статус «Виплачено» і час; Автор-засновник — Виплата 100% з позначкою. Окремого стану «Підтверджено, але не виплачено» джерела не задають.
- Notes For Design Brief: службова таблиця; числові колонки вирівняні праворуч.

## Responsive Structure Notes

- S-01: 1280 desktop відтворює V3 baseline 1:1; перший row із пʼяти Обкладинок не кліпається знизу. На 768 hero масштабується без зміни порядку, shelf лишається горизонтальним. На 390/430 shelf стає горизонтальним scroll-snap із 2–3 видимими квадратнокутними Обкладинками; навігація згортається в кероване меню, але пошук і Кошик лишаються за один клік; 4 плитки → 2 колонки; formula стає вертикальним блоком без накладання тексту; функціональні фільтри — у шторці; результати 2 → 1 колонка. Буквальне стискання desktop HTML заборонене як inaccessible drift.
- S-02: дві колонки → одна: обкладинка звужена зверху, CTA закріплюється внизу вʼюпорта на мобільному.
- S-03/S-04/S-06/S-07: форми й підсумки → одна колонка; позиції Кошика/Бібліотеки зберігають назву, ціну/формат і CTA без горизонтального скролу; модалі S-08/S-09 → bottom sheet або full-width dialog із trap focus.
- S-11/S-12: кроки P-5 горизонтальні → компактний індикатор «Крок 3 з 6»; Попередній перегляд видання на mobile відкривається на весь екран.
- S-13/S-14/S-16/S-17: секції й форми → одна колонка; фінансові/ліцензійні наслідки стоять безпосередньо перед CTA; fixed footer не перекриває помилки.
- S-15/S-19: таблиці → стековані рядки-картки на мобільному; числові підписи лишаються біля значень.
- S-18/S-20/S-21: master-detail → список, потім окрема detail-поверхня; деструктивні/фінансові підтвердження не стоять поруч без відступу. S-19 — стековані рядки; усі Менеджерські поверхні читабельні на mobile, хоча desktop лишається пріоритетом.

## Shared Patterns

- P-1 Публічний хедер baseline: transparent-background `UkieBook-logo-transparent.svg` без підкладки; `Каталог`, `Жанри`, `Знижки`, `Авторам`; пошук; Кошик із лічильником. Вхід/Бібліотека/меню профілю — authenticated state, який зберігає композиційну ієрархію та не прибирає baseline-навігацію.
- P-2 Картка книжки: квадратнокутна (`border-radius: 0`) обкладинка 2:3 з назвою, запеченою в реалістичний artwork, без live-text overlay; назва (1–2 рядки) під обкладинкою для семантики, автор, ціна / закреслена стара + нова, бейдж знижки. На S-01 сім повторно використовуваних слотів посилаються на сім різних artworks.
- P-3 Таблиця даних: заголовок, рядки, порожній стан із поясненням і CTA (де доречно).
- P-4 Статусний бейдж модерації: чернетка / на модерації / ручна перевірка / відхилено / опубліковано — однакова семантика в S-10, S-13, S-18.
- P-5 Крокований майстер: індикатор кроків, назад/далі, збереження чернетки.
- P-6 Модал підтвердження: заголовок-питання, наслідок дії, первинна + скасувати.

## State Variants

Перелік станів на екран — власність `docs/screen-map.md` (розділ Screen States); тут кожен стан описано як дельту в блупринті відповідного екрана. Наскрізні правила дельт:

- Завантаження: скелетон структури зони, не спінер на весь екран (де зона визначена).
- Порожньо: зона списку/таблиці замінюється поясненням + конструктивним CTA.
- Помилка: інлайн-повідомлення в зоні збою з дією повтору; глобальні помилки не перекривають увесь екран без потреби.
- Заборона доступу: редирект на S-03 або повідомлення про роль (Navigation Model зі screen-map).

## Content Priority Notes

- Мобільний пріоритет S-02: назва/автор → ціна → CTA → фрагмент → опис → відгуки.
- S-15: зведення і формула — над таблицями (довіра важливіша за деталізацію).
- S-11: одна дія на крок; жодних бічних відволікань у майстрі.
- За браком місця першими жертвуються: декоративні зони, потім вторинні дії; первинний CTA і статуси — ніколи.

## Cross-Screen Notes For Design Brief

- Статусна семантика P-4 має отримати єдину колірну мову в усіх ролях (автор бачить ті самі стани, що й менеджер у S-18).
- Гривневі суми (ціни, нарахування, виплати) — єдиний числовий стиль у S-02, S-04, S-15, S-19.
- Довірчі моменти продукту: формула Винагороди (S-01/S-15), Декларація прав і ліцензійна умова (S-11 крок 6), Попередній перегляд видання (S-12) — потребують спокійної, серйозної подачі.
- Климакс-стани (книжка опублікована; файли в бібліотеці після оплати) — два дозволені місця для виразного святкового акценту.
